# /close-out

作業を締める。品質チェックを実施し、問題なければコミットまで行う。

## 手順

1. **ファイル存在確認**
   今回の作業で「作成した・変更した」と記憶しているファイルが実際に存在するか `find` または `ls` で確認する。
   存在しないファイルがあった場合、規模を判断して対応を分ける。

   - **軽微なもの**（`__init__.py`、`.gitkeep` など中身がほぼ不要なファイル）→ 即作成してQA継続
   - **実装を伴うもの**（サービス・エージェント・MCPサーバーのコードファイル等）→ 以下を提示してユーザーに判断を委ねる
     1. 何のファイルが不足しているか
     2. 作成に必要なステップと推定コスト（小/中/大）
     3. 選択肢：「このままQAを中断して実装に戻る」または「QAの残りを続けて後で対処する」

2. **Python lint**
   ```bash
   make lint
   ```
   エラーがあれば修正してから次へ。

3. **Python テスト**
   `.test-passed` のタイムスタンプと、テスト対象ファイルの最終更新時刻を比較してスキップ可否を判断する。
   ```bash
   # .test-passed より新しいコードファイルがあるか確認 (CDK infrastructure を含む)
   find services/ mcp-servers/ agents/ infrastructure/ -newer .test-passed \( -name "*.py" \) 2>/dev/null | grep -v cdk.out | head -5
   ```
   - 出力が空（変更なし）→ **テストスキップ**。最終実行日時をユーザーに伝えて次へ進む
   - 出力あり（変更あり）または `.test-passed` が存在しない → `make test` を実行。失敗があれば修正してから次へ

4. **UI チェック** (`ui/` に変更がある場合のみ)
   ```bash
   find ui/src -newer .test-passed \( -name "*.ts" -o -name "*.tsx" \) 2>/dev/null | head -5
   ```
   - 出力が空 → **スキップ**
   - 出力あり → 以下を実行。エラーがあれば修正してから次へ
     ```bash
     npm --prefix ui run lint
     npm --prefix ui run type-check
     npm --prefix ui run build
     ```

5. **CDK 差分確認** (`infrastructure/` に変更がある場合、または前回デプロイ以降 infrastructure/ のファイルが変わった可能性がある場合)
   ```bash
   find infrastructure/ -newer .test-passed \( -name "*.py" \) 2>/dev/null | grep -v cdk.out | head -5
   ```
   - 出力が空 → **スキップ**
   - 出力あり → `make cdk-diff` を実行してシンセシスエラーやデプロイ差分を確認する。  
     エラー（例: Docker バンドリング失敗・型エラー）があれば修正してから次へ

6. **テスト用テーブルの後片付け確認**
   ```bash
   aws dynamodb list-tables --region us-east-1 --query "TableNames[?starts_with(@, 'agora-test-')]"
   ```
   残っていれば削除してよいかユーザーに確認する。

6. **変更内容の確認と進行判断**
   ```bash
   git diff --stat
   git status
   ```
   変更ファイルと差分の概要をユーザーに見せ、**必ず以下の選択肢を提示して確認を取る**。
   - **コミットに進む** — このままコミットする
   - **作業に戻る** — 追加修正や編集が必要。QAをここで終了する

   ユーザーが「作業に戻る」を選んだ場合はここで終了する。コミットは行わない。

7. **コミット**
   ユーザーの承認を得た場合のみ、コミットメッセージ案を提示してコミットする。
   コミットメッセージはCONCEPTで定義されているV1/V2/V3フェーズと関連する場合はそれを明記する。

8. **BACKLOG.md の更新**
   コミットが完了したら、今回の作業で完了したタスクを `BACKLOG.md` で `- [ ]` から `- [x]` に変更する。
   「現在のフォーカス」セクションの「次のタスク」も次の未完了タスクに更新する。

## 注意

- いずれかのステップで問題が見つかった場合は修正を優先し、全部パスしてからコミットに進む。
- プッシュはコミット後にユーザーが希望した場合のみ行う。
- BACKLOG.md 自体の更新もコミットに含めてよい（同一コミットでまとめる）。
